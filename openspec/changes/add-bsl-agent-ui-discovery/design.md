## Контекст
`bsl-agent` может поднимать локальный HTTP UI (localhost-only) с автоподбором порта (`127.0.0.1:0`). При параллельной работе нескольких агентов в одном `BSL_CACHE_DIR` нужен механизм discovery, позволяющий узнать `http://localhost:<port>` конкретного инстанса без парсинга логов и без обращения к внешним утилитам (`ss/lsof`).

Ключевое требование безопасности/предсказуемости: если найдено несколько кандидатов и пользователь не уточнил, какой нужен, команда НЕ должна выбирать “наугад” и должна завершаться ошибкой.

## Варианты
### 1) Парсить логи
Плюсы: ничего не менять в рантайме.
Минусы: ненадёжно (формат/уровни, смешивание логов), неудобно для скриптов.

### 2) Сканировать сокеты (`ss`, `/proc/net/tcp`) и сопоставлять PID
Плюсы: без изменений в `bsl-agent`.
Минусы: платформенные зависимости, права/доступ, сложно в тестах, не переносимо, неудобно для пользователей.

### 3) Runtime registry (portfile/registry) + CLI
Плюсы: детерминированно, кроссплатформенно в пределах целевой среды, легко тестировать.
Минусы: нужно поддерживать “протухшие” записи после крашей.

Выбор: вариант 3.

## Решение
### Registry запись (одна на инстанс)
При успешном bind HTTP UI `bsl-agent` записывает registry запись с фактическим адресом/портом.

Расположение: под state root `bsl-agent` (derived from `BSL_CACHE_DIR` и XDG/HOME fallbacks), например:
- `<state_root>/runtime/http-ui/<instance_id>.json`

Минимальные поля записи:
- `instance_id`: строка (уникальный ID процесса)
- `pid`: целое число (PID процесса)
- `started_at`: unix secs
- `addr`: строка (`127.0.0.1:<port>`)
- `ui_url`: строка (`http://localhost:<port>`)

Запись должна быть атомарной (write temp + rename) чтобы избежать частичных файлов и гонок.

### CLI discovery
Добавляются сабкоманды `bsl-agent ui ...`:
- `ui list`: выводит найденные записи; по умолчанию только “живые”.
- `ui url`: печатает plain `ui_url` при единственном совпадении; при неоднозначности — ошибка + список кандидатов.

Определение “живой” записи:
- основной способ: healthcheck `GET {ui_url}/api/mcp/status` с коротким таймаутом;
- опциональный fallback: проверка существования `/proc/<pid>` (если необходимо).

Выбор нужного инстанса:
- `--instance-id <id>`: выбрать конкретную запись;
- `--pid <pid>`: выбрать запись процесса;
- `--roots <path>`: выбрать инстанс, у которого `GET /api/mcp/sessions` содержит `roots[]` с точным совпадением строки root.

## Примечания
- Registry хранится в `BSL_CACHE_DIR`, поэтому для корректной работы CLI пользователь должен запускать `bsl-agent ui ...` с тем же `BSL_CACHE_DIR`, что и целевой инстанс.
- Стабильность вывода: `ui url` должен печатать только URL (без префиксов), чтобы его можно было использовать в скриптах.
