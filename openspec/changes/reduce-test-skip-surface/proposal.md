# Предложение изменений: Сокращение «поверхности пропуска тестов» (`#[ignore]`, `tests/disabled`)

## Зачем
В репозитории есть значимое число тестов, которые не запускаются по умолчанию:
- `#[ignore]` в `backend/tests/**`,
- набор `tests/disabled/*`.

Это формирует техдолг:
- снижается доверие к тестовому покрытию (часть проверок никогда не выполняется);
- растёт риск регрессий в важных сценариях;
- разработчикам неочевидно, что именно считается «smoke» и что требует внешних фикстур.

## Что меняется
- Ввести явную политику тестовых уровней:
  - **smoke**: должен проходить из чистого checkout без внешних данных (без Syntax Helper архива и т.п.).
  - **full/manual**: может требовать внешние фикстуры/подготовку и запускаться вручную.
- Пересмотреть `#[ignore]` и `tests/disabled/*`:
  - часть тестов перевести в smoke (если реально возможно);
  - остальные — явно пометить как manual/heavy с документированными требованиями.
- Уточнить команды запуска для каждого уровня (через существующие скрипты в `scripts/`).

## Не цели
- Реализация отсутствующих крупных функций (CFG/полный flow-sensitive), если тесты падают из‑за реально недореализованных фич.
- Подключение CI (это отдельный change).

## Влияние
- Может измениться набор тестов, запускаемых по умолчанию локально.
- Улучшится прозрачность и предсказуемость тестового процесса.

## Критерии готовности
- Есть документированная политика: что smoke, что manual/heavy и как это запускать.
- Количество `#[ignore]`/`tests/disabled` снижено или классифицировано (не «просто отключено»).
