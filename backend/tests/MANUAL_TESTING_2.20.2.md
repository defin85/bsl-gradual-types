## Сценарий 3: ETA точность

### Описание
Проверяет что оценка оставшегося времени (ETA) достаточно точная (погрешность <= 20%).

### Шаги выполнения

1. **Записать время начала индексации**
   - Засечь время BEGIN notification

2. **Записать промежуточные ETA**
   - При 25% прогресса: ETA = ?
   - При 50% прогресса: ETA = ?
   - При 75% прогресса: ETA = ?

3. **Записать время завершения**
   - Засечь время END notification

4. **Вычислить точность**

### Пример измерений

```
T = 0s:   BEGIN - 0%
T = 20s:  REPORT - 25%, ETA: 60s   ← Прогноз: 20s + 60s = 80s total
T = 40s:  REPORT - 50%, ETA: 40s   ← Прогноз: 40s + 40s = 80s total
T = 60s:  REPORT - 75%, ETA: 20s   ← Прогноз: 60s + 20s = 80s total
T = 85s:  END - 100%                ← Реально: 85s total
```

### Формула точности

```
Прогноз = текущее_время + ETA
Реальное = END timestamp - BEGIN timestamp
Погрешность = |Прогноз - Реальное| / Реальное * 100%
```

### Пример расчёта

```
Прогноз (при 50%): 40s + 40s = 80s
Реальное: 85s
Погрешность: |80 - 85| / 85 * 100% = 5.9%  ✅ Отлично!
```

### Критерии приёмки

- [ ] ✅ ETA точность >= 80% (погрешность <= 20%)
- [ ] ✅ ETA уменьшается по мере прогресса
- [ ] ✅ При прогрессе < 5% ETA не показывается (too early)
- [ ] ✅ ETA разумная (не показывает 999 секунд или 0 секунд)

### Как записать результаты

```markdown
## Результаты Сценария 3

| Прогресс | Время (сек) | ETA (сек) | Прогноз total | Реальное total | Погрешность |
|----------|-------------|-----------|---------------|----------------|-------------|
| 25%      | 20s         | 60s       | 80s           | 85s            | 5.9% ✅     |
| 50%      | 40s         | 40s       | 80s           | 85s            | 5.9% ✅     |
| 75%      | 60s         | 20s       | 80s           | 85s            | 5.9% ✅     |

**Вывод:** ETA точность = ХХ% (отлично/хорошо/плохо)
```

## Сценарий 4: Обработка ошибок

### Описание
Проверяет корректную обработку ошибок при невалидном пути к Syntax Helper.

### Шаги выполнения

1. **Изменить путь в настройках Extension**
   - File → Preferences → Settings
   - Найти `bslAnalyzer.syntaxHelperPath`
   - Установить невалидный путь: `C:\invalid\path`

2. **Перезапустить LSP Server**
   - Command Palette (Ctrl+Shift+P)
   - "Reload Window"

3. **Открыть `.bsl` файл**
   - LSP должен попытаться загрузить типы

4. **Наблюдать Output Channel**

### Ожидаемый результат

**Output Channel должен показывать:**

```
[LSP] Initializing BSL Language Server...
[LSP] Загружаем типы платформы из: C:\invalid\path

[$/progress] BEGIN - Title: Загрузка типов платформы 1С, Percentage: 0%
🚀 Index building started with 4 steps

ERROR: Не удалось прочитать файлы: No such file or directory (os error 2)

[$/progress] END - Message: ❌ Ошибка загрузки: файл не найден
❌ Ошибка загрузки: файл не найден
```

**Status Bar должен показывать:**

```
$(error) BSL: Disconnected
```

**Tooltip Status Bar:**

```
BSL Language Server не активен
Проверьте логи для деталей
```

### Критерии приёмки

- [ ] ✅ END notification с ошибкой отправляется
- [ ] ✅ Status Bar показывает ошибку (красный фон)
- [ ] ✅ Pending throttled updates отменены (нет "висящих" процентов)
- [ ] ✅ Output Channel показывает понятное сообщение об ошибке
- [ ] ✅ Extension НЕ зависает и НЕ крашится

### Как записать результаты


```

```
