# Change: add-bsl-agent-ui-discovery

## Зачем
`bsl-agent` поддерживает опциональный HTTP UI (localhost-only) и может быть запущен с автоподбором порта (`127.0.0.1:0`). В сценарии, когда одновременно запущено несколько `bsl-agent` в одном `BSL_CACHE_DIR`, разработчику и скриптам нужен надёжный способ узнать адрес и порт UI **конкретного** инстанса.

Текущий подход через лог-строку “http ui listening on …” неудобен и ненадёжен:
- вывод может быть недоступен/смешан с другими логами;
- порт автоподбирается и меняется на каждом запуске;
- при нескольких инстансах требуется безопасный выбор (без “угадываний”).

## Что меняется
- `bsl-agent` при включённом HTTP UI записывает “runtime discovery” запись (registry) с фактическим `ui_url` после bind.
- В `bsl-agent` добавляются CLI сабкоманды `bsl-agent ui ...` для получения URL:
  - `bsl-agent ui list` — показать найденные инстансы UI (по умолчанию только “живые”);
  - `bsl-agent ui url` — вывести `http://localhost:<port>` для ровно одного инстанса; при неоднозначности (несколько) — ошибка и подсказка, как выбрать инстанс.

## Влияние
- Затронутая спецификация: `openspec/specs/mcp-bsl-agent/spec.md` (добавляются требования про registry и CLI discovery).
- Затронутый код (на стадии реализации): `bsl-agent` (CLI, запись registry).

## Не цели (Non-goals)
- Не добавляем внешний отдельный бинарник (`bsl-agent-ui`) — всё внутри `bsl-agent`.
- Не добавляем автоматический выбор “последнего” инстанса при неоднозначности: при >1 инстансе без селектора команда должна завершаться ошибкой (безопасное поведение).
- Не меняем HTTP API UI (используем уже существующие read-only эндпоинты `/api/mcp/status` и `/api/mcp/sessions`).
