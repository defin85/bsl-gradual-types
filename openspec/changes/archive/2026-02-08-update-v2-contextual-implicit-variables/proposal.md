# Change: Context-aware implicit переменные модулей в IntelliSense v2

## Why
В реальных модулях форм из `conf_big` v2 pipeline выдаёт ложные diagnostics `Необъявленная переменная` для платформенных implicit-переменных (`ЭтотОбъект`, `Объект`, `Форма`, `Параметры`). Это ломает точность семантической диагностики и ухудшает UX IntelliSense в типовых сценариях `ПриСозданииНаСервере`.

Проблема усугубляется тем, что биндинги implicit-символов сейчас не унифицированы между AST→IR и type inference, а поведение не специфицировано по фасетам модуля (`FormModule`, `ManagerModule`, `ObjectModule`) и директивам `*БезКонтекста`.

## What Changes
- Добавить в `bsl-intellisense-v2` требования к контекстно-зависимым implicit-переменным модулей.
- Зафиксировать матрицу биндингов для:
  - `FormModule`: `ЭтотОбъект`, `ЭтаФорма`, `Форма`, `Объект`, `Элементы`, `Параметры`.
  - `ManagerModule`: `ЭтотОбъект`, `Объект`.
  - `ObjectModule`/`RecordSetModule`: `ЭтотОбъект`, `Объект`.
- Зафиксировать выбранную политику: в `FormModule` переменная `Параметры` имеет тип `Структура`.
- Зафиксировать правило для `&НаСервереБезКонтекста` и `&НаКлиентеНаСервереБезКонтекста`: context-bound переменные формы недоступны.
- Зафиксировать требование, что корректные implicit-переменные в поддерживаемом контексте MUST NOT диагностироваться как `Необъявленная переменная`.

## Impact
- Affected specs: `bsl-intellisense-v2`
- Affected code (implementation follow-up):
  - `analysis-v2/src/ast_to_ir/converter.rs`
  - `analysis-v2/src/type_inference_v2.rs`
  - общий модуль правил implicit-биндингов (новый файл/модуль в `analysis-v2`)
  - интеграционные тесты diagnostics/hover/completion для form/manager модулей

## Non-Goals
- Полное моделирование всех платформенных переменных 1С во всех типах модулей.
- Ретрофит legacy inference путей (изменение ограничено v2 pipeline).
- Изменение бизнес-логики runtime конфигурации или parsing синтаксиса.
