# Change: audit-bsl-intellisense

## Why
Сейчас в репозитории уже есть LSP‑сервер, VS Code extension и MCP `bsl-agent`, но “что именно умеет IntelliSense” описано фрагментарно (roadmap’ы/доки/код). Нужен единый, проверяемый по исходникам “инвентарь” возможностей IntelliSense для BSL (1С) и фиксация текущего контракта, чтобы:
- быстро отвечать на вопросы “что поддерживается / что отсутствует”,
- отличать реальные фичи от заглушек/планов,
- планировать дальнейшее доведение до IDE‑grade без повторного “археологического” анализа.

## What Changes
- Добавить спецификацию capability `bsl-intellisense` (текущая правда: LSP + VS Code integration), без расширения функциональности.
- Зафиксировать audit‑матрицу “функция IntelliSense → статус → evidence” в `design.md` текущего change (с ссылками на файлы/строки).
- Сформулировать список выявленных gap’ов как follow‑ups (отдельные будущие change‑proposal’ы), без реализации в рамках этого change.

## Impact
- Новая спецификация: `openspec/specs/bsl-intellisense/spec.md` (через change).
- Код и поведение: **без изменений** (change про аудит/контракты/документацию).
