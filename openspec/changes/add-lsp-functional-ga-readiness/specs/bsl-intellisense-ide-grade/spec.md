## ADDED Requirements

### Requirement: Функциональный GA baseline на `conf_big` обязателен для IntelliSense качества (MUST)
Система MUST иметь и поддерживать минимальный acceptance-профиль на `examples/conf_big`, который используется как функциональный gate перед коммерческим релизом.

Acceptance-профиль MUST включать как минимум:
- сценарии контекстных implicit symbols (Form/Manager/Object contexts),
- сценарии typed-row `ТаблицаЗначений`,
- сценарии неполного кода при редактировании.

#### Scenario: Базовый `conf_big` профиль проходит без блокирующих функциональных дефектов
- **GIVEN** релизный кандидат LSP и зафиксированный smoke-набор `conf_big`
- **WHEN** выполняется функциональная проверка IntelliSense сценариев
- **THEN** все обязательные сценарии профиля проходят и релиз считается функционально GA-ready

### Requirement: Поддерживаемые context implicit symbols не дают FP `UndeclaredVariable` (MUST)
Для символов, которые заявлены поддерживаемыми в текущем модульном контексте, система MUST NOT публиковать ложные diagnostics `Необъявленная переменная`.

Требование распространяется минимум на:
- `ЭтотОбъект`/`Объект` для Manager/Object contexts,
- `ЭтотОбъект`/`Форма`/`ЭтаФорма`/`Элементы`/`Параметры` для Form context (с учетом правил `*БезКонтекста`).

#### Scenario: Валидный form-context не порождает FP по `ЭтотОбъект` и `Параметры`
- **GIVEN** в модуле формы есть валидный вызов `...ПриСозданииНаСервереДокумент(ЭтотОбъект, Параметры)`
- **WHEN** LSP публикует semantic diagnostics
- **THEN** диагностики `Необъявленная переменная` для `ЭтотОбъект` и `Параметры` отсутствуют

### Requirement: Typed-row `ТаблицаЗначений` ведет себя консистентно в completion/hover/diagnostics (MUST)
Если строка получена из таблицы со статически известной схемой колонок, система MUST давать согласованное поведение во всех IDE операциях:
- completion на `Стр.` показывает доступные колонки,
- hover/type-at-position для `Стр.<Колонка>` возвращает тип колонки,
- неизвестная колонка дает диагностируемую ошибку, а не silent fallback.

#### Scenario: Колонки таблицы доступны сквозным образом в IDE
- **GIVEN** функция формирует `ТаблицаЗначений` и добавляет колонки через `Колонки.Добавить`
- **AND** код работает со строкой этой таблицы
- **WHEN** IDE выполняет completion/hover/diagnostics
- **THEN** известные колонки резолвятся единообразно, а неизвестные диагностируются как ошибка свойства

### Requirement: Неполный код не должен ломать базовую IntelliSense функциональность (MUST)
В условиях синтаксически неполного текста (незакрытые скобки/частично набранные выражения) система MUST продолжать предоставлять базовые IntelliSense ответы и MUST не деградировать в массовые нерелевантные diagnostics.

#### Scenario: Пользователь редактирует неполное выражение
- **GIVEN** документ содержит неполный код в текущей позиции курсора
- **WHEN** IDE запрашивает completion и hover
- **THEN** сервер возвращает предсказуемый результат без падения и без лавинообразного шума диагностик
