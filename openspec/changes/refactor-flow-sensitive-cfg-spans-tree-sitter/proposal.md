# Change: Tree-sitter‑точные spans для CFG v2 (все Conditional) + LSP тест на TypeGuard completion

## Почему
В `update-flow-sensitive-cfg-stability` стабилизировали базовый контракт CFG v2 (CFG всегда есть, детерминированный mapping `byte offset → CFG node`, loop header учитывается в null-safety).
Однако остались критичные пробелы, которые мешают гарантировать стабильное flow-sensitive поведение:

- Spans для `If`/циклов в CFG v2 вычисляются по строковому поиску ключевых слов (эвристика), что может ломаться на вложенных `Если/Иначе/ИначеЕсли` и других нетривиальных форматированиях.
- Контракт header/body spans не применён ко всем `CfgNodeKind::Conditional`: `Try/Except` сейчас представлен как `Conditional`, но не имеет отдельных marker-узлов и spans тела веток.
- Нет интеграционного LSP теста, который закрепляет сценарий из требований: completion на `x.` внутри `Если ТипЗнч(x)=Тип("...") Тогда ...` должен выбирать контекст ветки и учитывать narrowing.

Это сохраняет риск регрессий (в особенности на границах токенов и в условных ветках), и не даёт “доказательства через тест” для самого важного пользовательского сценария.

## Что меняется
- Spans header/body для `If`/циклов/`TryExcept` в CFG v2 становятся структурно корректными и вычисляются из tree-sitter (через `syntax`/tree_sitter_adapter), без строковых эвристик.
- Контракт header/body применяется ко всем `CfgNodeKind::Conditional`, включая `TryExcept`:
  - header span не пересекается с телом,
  - у каждой ветки/тела есть отдельный CFG узел-маркер со span тела (включая пустые ветки).
- Добавляется интеграционный тест LSP completion, закрепляющий сценарий:
  - `Если ТипЗнч(x) = Тип("ТаблицаЗначений") Тогда x.` → completion включает ожидаемый member (например, `Колонки`) и не “проваливается” из-за неверного CFG mapping.

## Влияние
- Затрагиваемые спецификации: `bsl-intellisense-v2` (позиционирование, flow-sensitive).
- Затрагиваемые подсистемы:
  - `syntax/` (AST/adapter: вычисление body spans из tree-sitter),
  - `analysis-v2/` (CFG builder: использование структурных spans и покрытие `TryExcept`),
  - `backend/` (интеграционные LSP тесты completion).

## Не цели
- Не менять общий дизайн `node_at_byte_offset`/bias (если не потребуется для прохождения тестов).
- Не расширять набор type guards — используем существующий `ТипЗнч(x)=Тип("...")`.
- Не делать оптимизаций производительности (интервальные индексы) — только корректность и тестовая фиксация.
