# Design: Локальный return inference в v2 (sound + union + SCC)

## Context
В BSL:
- локальные функции/процедуры модуля доступны для вызова до объявления (forward reference);
- внутри модуля можно вызывать неэкспортные методы;
- если управление доходит до `КонецФункции`, функция возвращает `Неопределено` неявно (семантика “implicit return”).

В архитектуре проекта:
- `SignatureIndex` — глобальный индекс сигнатур платформы/конфигурации; он не должен зависеть от open-file состояния;
- `bsl-analysis-v2` — единственный источник истины типового вывода для IDE/Web/MCP.

## Goals
- Корректно (sound) выводить тип выражения вызова `F()` для функций текущего файла, включая forward reference.
- Поддерживать `union` по нескольким `Возврат`.
- Корректно и детерминированно обрабатывать взаимные вызовы и рекурсию без “магических” лимитов итераций.
- Оставаться быстрыми на больших модулях (инкрементальность/кэширование).

## Proposed Approach
### 1) Локальные summaries (per-file)
Ввести пер-файловую структуру “локальные summaries функций”:
- `return_type: TypeResolution` — итоговый тип возврата
- `may_fallthrough: bool` — возможен ли выход без явного `Возврат` (тогда в `return_type` MUST присутствовать `Неопределено`)

`may_fallthrough`:
- предпочтительно вычислять на основе уже существующего CFG/IR (как более точный источник control-flow);
- допустима консервативная аппроксимация по AST на первом этапе реализации, если она sound (то есть в сомнительных случаях считать fallthrough возможным).

### 2) Call graph и SCC
Построить локальный граф вызовов по AST текущего файла:
- узлы: только `FunctionDecl` (процедуры игнорируются для return-типа вызова)
- ребро `A → B`, если в теле `A` встречается вызов `B()` по короткому имени, и `B` — локальная функция файла

Сжать граф в SCC и обрабатывать SCC в топологическом порядке.

### 3) Solver: fixed-point/worklist внутри SCC
Для каждой функции `F` внутри SCC:
- собрать типы выражений во всех `Возврат <expr>` как `T_i`;
- итоговый `return_type` = `Union(T_i)`; если `Возврат` без значения → добавить `Неопределено`;
- если `may_fallthrough` истинно → добавить `Неопределено` (implicit return);
- если встречается `Unknown/Dynamic` → итоговый тип становится “верхним” (по правилам `TypeResolution`, `Union` с Dynamic нормализуется в Dynamic).

Поскольку типы возвратов зависят от типов выражений, а выражения могут содержать вызовы локальных функций, solver должен работать по fixed-point:
- начальные summaries: `Unknown` (или `Неопределено` для функций без `Return`, если доказан fallthrough);
- итеративно пересчитывать `return_type` до стабилизации;
- критерий остановки: изменения `return_type` ни для одной функции в SCC.

Требование “не MVP” означает:
- НЕ использовать “жёсткий лимит итераций” как единственный механизм завершения;
- использовать структурное завершение через SCC (и при необходимости widening-политику, явно описанную в коде/тестах).

### 4) Интеграция в type inference
При выводе типа для `Call(Identifier)`:
1. Если имя соответствует локальной функции файла и её `return_type` уже известен в summaries → использовать его.
2. Иначе fallback на глобальные источники (`SignatureIndex` / metadata lookup), как сейчас.

Итог: `type_at_byte_offset`/hover/completion получают корректный тип вызова локальной функции без изменения публичных интерфейсов.

## Alternatives Considered
### A) Класть локальные функции в глобальный SignatureIndex
Отклонено: это смешивает file-local состояние с глобальным индексом конфигурации/платформы, усложняет инкрементальность/инвалидацию и создаёт риск коллизий имён между файлами.

### B) Строить полноценный межфайловый call graph по неэкспортным вызовам
Вне scope: это существенно более широкий interprocedural анализ и требует отдельного change.

## Test Strategy
- Юнит‑тесты на минимальных BSL‑сниппетах:
  - forward reference (вызов до объявления) с корректным return типом;
  - несколько `Возврат` с union;
  - ветка без `Возврат` → добавление `Неопределено`;
  - рекурсия и взаимная рекурсия (SCC) — детерминированный результат.
- Регрессия на реальном примере из `examples/conf_big/CommonModules/.../Module.bsl`.
