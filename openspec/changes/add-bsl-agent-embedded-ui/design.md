## Контекст
HTTP UI `bsl-agent` раздаёт SPA. Сейчас статика берётся из директории на диске (по умолчанию `target/site`). Это требует, чтобы пользователь получил/собрал фронтенд отдельно.

## Требования
- UI должен работать без внешней статики (embedded по умолчанию).
- `BSL_AGENT_HTTP_STATIC_DIR` должен иметь приоритет над embedded (для dev/override).
- Сборка `bsl-agent` должна падать, если `target/site` не собран, с понятной ошибкой.

## Варианты реализации embed
### 1) `include_bytes!` / вручную
Плюсы: минимум зависимостей.
Минусы: неудобно для набора файлов (особенно hashed assets), сложно поддерживать.

### 2) Встраивание директории через специализированный crate (например `include_dir`/`rust-embed`)
Плюсы: просто встраивать дерево файлов; удобно для hashed assets; можно отдавать файлы по пути.
Минусы: добавляется зависимость.

Выбор: вариант 2 (встраивание директории).

## Build-time проверка
Добавить `build.rs` в `bsl-agent`, который проверяет наличие `../target/site/index.html` (и, при необходимости, типичных ассетов) и завершает сборку с понятным сообщением:
“UI assets not found: build frontend first (trunk build ...)”.

Это исключает ситуацию, когда бинарник собран, но UI фактически не работает.

## Runtime приоритет
При старте HTTP UI:
1) Если задан `BSL_AGENT_HTTP_STATIC_DIR` и директория существует → раздавать `ServeDir` с диска (как сейчас).
2) Иначе → раздавать embedded файловый набор.

В обоих режимах сохраняется SPA fallback на `index.html` для client-side роутинга.
