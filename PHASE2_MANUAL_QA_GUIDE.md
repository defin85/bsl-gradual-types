# MILESTONE 3.6 Phase 2 - Manual QA Guide

Этот документ содержит инструкции для ручного тестирования Phase 2 features в VSCode Extension.

---

## Предварительная подготовка

### 1. Сборка LSP сервера (Release build)

```bash
cd /c/1CProject/bsl-gradual-types

# Собрать LSP сервер в режиме Release
cargo build --release -p bsl-backend --bin bsl-lsp-server

# Результат будет здесь:
# target/release/bsl-lsp-server.exe
```

### 2. Установка Syntax Helper (опционально, но рекомендуется)

```bash
# Option A: Использовать встроенный Syntax Helper
# - LSP сервер автоматически найдёт examples/syntax_helper

# Option B: Установить environment variable
set BSL_SYNTAX_HELPER_PATH=C:\1CProject\bsl-gradual-types\examples\syntax_helper
```

### 3. Подготовка VSCode Extension

```bash
# Собрать extension с новым LSP сервером
cd frontend/extension
npm run build

# Или открыть VSCode Extension Development Host:
# - Нажать F5 в VSCode (при открытой папке frontend/extension)
```

## Сценарии тестирования

### Сценарий A: Фасеты в Hover

**Цель:** Проверить что фасеты отображаются в DetailLevel::Detailed

**Код для тестирования:**
```bsl
Процедура ТестФасетов()
    // Тест 1: Reference фасет для Справочника
    КонтрагентСсылка = Справочники.Контрагенты.НайтиПоНаименованию("ООО Рога");
    КонтрагентСсылка.Наименование; // Hover на КонтрагентСсылка

    // Тест 2: Object фасет для Справочника
    КонтрагентОбъект = Справочники.Контрагенты.НайтиПоКоду("001");
    КонтрагентОбъект.Наименование; // Hover на КонтрагентОбъект

    // Тест 3: Примитивный тип (НЕ должно быть фасетов)
    Число = 42; // Hover на Число - НЕ должно быть "Фасет:"
КонецПроцедуры
```

**Шаги:**

1. Создать файл .bsl с кодом выше
2. Установить `detailLevel: "detailed"` в VSCode settings (если доступно)
3. Навести курсор на `КонтрагентСсылка`
4. **Ожидаемый результат:**
   ```
   СправочникСсылка.Контрагенты

   💡 Фасет: Reference (ссылка на элемент)

   💡 Доступные фасеты:
   • Manager
   • Object
   • Reference
   • Selection
   ```

5. Навести на `КонтрагентОбъект`
6. **Ожидаемый результат:**
   ```
   ДокументОбъект.ЗаказКлиента

   💡 Фасет: Object (объект с данными)

   💡 Доступные фасеты:
   • Manager
   • Object
   ```

7. Навести на `Число`
8. **Ожидаемый результат:**
   ```
   Число

   (НЕ должно быть секции "Фасет:")
   ```

**Проверка:**
- ✅ Reference фасет видимый для Справочника
- ✅ Object фасет видимый для Документа
- ✅ Доступные фасеты перечислены
- ✅ Примитивные типы НЕ показывают фасеты
- ✅ Это видно ТОЛЬКО в DetailLevel::Detailed (переключить на Compact/Full и проверить)

### Сценарий B: Generic типы

**Цель:** Проверить что Generic типы объясняются с контекстом

**Код для тестирования:**
```bsl
Процедура ТестGenericТипов()
    // Тест 1: Array<String>
    МассивСтрок = Новый Массив();
    МассивСтрок.Добавить("Элемент 1");
    МассивСтрок.Добавить("Элемент 2");
    // Hover на МассивСтрок

    // Тест 2: Map<Number, String>
    Соответствие = Новый Соответствие();
    Соответствие.Вставить(1, "Один");
    Соответствие.Вставить(2, "Два");
    // Hover на Соответствие

    // Тест 3: ValueTable
    ТЗ = Новый ТаблицаЗначений();
    ТЗ.Колонки.Добавить("Имя");
    ТЗ.Колонки.Добавить("Значение");
    // Hover на ТЗ
КонецПроцедуры
```

**Шаги:**

1. Создать файл .bsl с кодом выше
2. Установить DetailLevel::Detailed
3. Навести на `МассивСтрок`
4. **Ожидаемый результат:**
   ```
   Массив

   💡 Generic тип:
   • Базовый тип: Массив
   • Параметры типа: Строка

   ℹ️ Generic тип означает, что массив содержит элементы определённого типа.
   Вы можете добавлять только элементы указанного типа.
   ```

5. Навести на `Соответствие`
6. **Ожидаемый результат:**
   ```
   Соответствие

   💡 Generic тип:
   • Базовый тип: Соответствие
   • Параметры типа: Число, Строка

   ℹ️ Generic тип означает, что соответствие... (специализированное объяснение)
   ```

7. Навести на `ТЗ`
8. **Ожидаемый результат:**
   ```
   ТаблицаЗначений

   (Если Generic информация доступна):
   💡 Generic тип:
   • Базовый тип: ТаблицаЗначений
   ```

**Проверка:**
- ✅ Generic пояснение показано
- ✅ Базовый тип указан
- ✅ Все параметры типа перечислены
- ✅ Контекстное объяснение соответствует типу
- ✅ Это видно ТОЛЬКО в DetailLevel::Detailed

### Сценарий C: Документация ссылки

**Цель:** Проверить что документация линкуется корректно

**Код для тестирования:**
```bsl
Процедура ТестДокументации()
    // Тест 1: С Syntax Helper
    ТЗ = Новый ТаблицаЗначений();
    // Hover на ТЗ - должны быть локальная + онлайн ссылки

    // Тест 2: Сложный тип
    Справочник = Справочники.Контрагенты;
    // Hover на Справочник - должна быть онлайн ссылка

    // Тест 3: Generic тип
    МассивСтрок = Новый Массив();
    // Hover на МассивСтрок - ссылка на "Массив"
КонецПроцедуры
```

**Шаги:**

1. Создать файл .bsl с кодом выше
2. Убедиться что **Syntax Helper доступен** (examples/syntax_helper должен быть в проекте)
3. Установить DetailLevel::Detailed
4. Навести на `ТЗ`
5. **Ожидаемый результат:**
   ```
   ТаблицаЗначений

   ...другая информация...

   📚 Документация:
   • [Синтаксис Помощник: ТаблицаЗначений](file:///.../examples/syntax_helper/ТаблицаЗначений.html)
   • [1С Platform Docs](https://docs.1c.ru/search?q=ТаблицаЗначений)
   ```

6. **Кликнуть на первую ссылку**
7. **Ожидаемый результат:**
   - Должна открыться браузер с локальной HTML страницей из Syntax Helper
   - Страница должна содержать информацию о ТаблицаЗначений

8. **Кликнуть на вторую ссылку**
9. **Ожидаемый результат:**
   - Должна открыться страница https://docs.1c.ru/search?q=ТаблицаЗначений
   - Поиск ТаблицаЗначений на сайте 1С документации

10. Навести на `Справочник`
11. **Ожидаемый результат:**
    ```
    Справочники (или уточнённый тип)

    📚 Документация:
    • [1С Platform Docs](https://docs.1c.ru/search?q=Справочники)
    ```

**Проверка:**
- ✅ Обе ссылки (локальная и онлайн) видны с Syntax Helper
- ✅ Без Syntax Helper видна только онлайн ссылка
- ✅ Клик на ссылку открывает браузер
- ✅ Для Generic типов ссылка ведёт на базовый тип
- ✅ Это видно ТОЛЬКО в DetailLevel::Detailed

**Цель:** Проверить что Phase 2 features ТОЛЬКО в Detailed уровне

**Код для тестирования:**
```bsl

```

1. Создать файл .bsl с кодом выше

2. **Навести на КонтрагентСсылка с DetailLevel::Compact**


   - **Ожидаемый результат:**
     ```

     • Существует(): Булево
     • ПолучитьСтроковоеПредставление(): Строка

     ```

4. **Навести на КонтрагентСсылка с DetailLevel::Detailed**
   - **Ожидаемый результат:**
     ```
     СправочникСсылка.Контрагенты

     💡 Фасет: Reference
     💡 Доступные фасеты: Manager, Object, Reference, Selection

     Методы:
     (все методы)

     📚 Документация:
     (обе ссылки)
     ```

**Проверка:**
- ✅ Compact: только тип
- ✅ Full: тип + методы, БЕЗ фасетов/документации
- ✅ Detailed: всё вместе

## Troubleshooting

### Проблема: Фасеты НЕ показываются

**Возможные причины:**
1. DetailLevel НЕ Detailed
   - **Решение:** Проверить settings.json в VSCode
2. LSP сервер старый
   - **Решение:** Пересобрать: `cargo build --release -p bsl-backend --bin bsl-lsp-server`
3. Тип НЕ поддерживает фасеты (примитивный)
   - **Решение:** Тестировать на типах как СправочникСсылка

### Проблема: Generic пояснение НЕ показывается

**Возможные причины:**
1. Type resolution вернул неправильный тип
   - **Решение:** Проверить логи LSP сервера
2. DetailLevel НЕ Detailed
   - **Решение:** Переключиться на Detailed

### Проблема: Документация ссылки НЕ работают

**Возможные причины:**
1. Syntax Helper НЕ доступен
   - **Решение:** Проверить `examples/syntax_helper` существует
2. Онлайн ссылка неправильная
   - **Решение:** Проверить что URL соответствует типу: `https://docs.1c.ru/search?q=ТипИмя`
3. File:// ссылка НЕ работает на Windows
   - **Решение:** Проверить что path преобразуется правильно (Windows paths → file:///)

### Проблема: Combo (Фасет + Generic + Документация) НЕ работает

**Возможные причины:**
1. Type НЕ имеет всех параметров
   - **Решение:** Использовать типы которые имеют и фасеты И Generic информацию
2. HoverBuilder rendering error
   - **Решение:** Проверить логи: `cargo run --bin bsl-lsp-server 2>&1 | grep -i error`

## Notes для QA Engineers

1. **Localization:** Все текст фасетов и Generic объяснений должны быть на русском для русской конфигурации, англий для англоязычной
2. **Platform types:** Убедитесь что используете актуальную версию Syntax Helper (из examples/)
3. **File paths:** На Windows использовать escaped paths в URLs: `file:///C:/path/to/file` (НЕ `file:///C:\path\to\file`)
4. **LSP reload:** Если что-то сломалось, перезагрузить VSCode полностью (Ctrl+Shift+P → "Developer: Reload Window")
