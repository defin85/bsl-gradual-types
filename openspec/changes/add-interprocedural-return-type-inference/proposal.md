## Зачем (Problem / Value)

Сейчас вывод возвращаемого типа пользовательских функций/процедур фактически не поддерживает межфайловые зависимости и рекурсию:

- в `analysis-v2` нет межпроцедурного вывода return-типа (вызовы пользовательских функций часто остаются `Unknown`/`Неопределено`);
- в индексации BSL-модулей конфигурации return-типы извлекаются локально и не учитывают вызовы других функций/модулей, поэтому экспортные сигнатуры в `SignatureIndex` неточные;
- попытки “пост‑пассом” дописывать типы неустойчивы, потому что return-типы и типы вызовов взаимозависимы и требуют фикс‑пойнта.

Пользовательский эффект:

- completion/hover/diagnostics хуже на реальных конфигурациях: `X = ФункцияИзОбщегоМодуля();` не получает тип, хотя он выводим из тела экспортной функции;
- после правок в открытых файлах IDE не видит обновлённые return-типы для вызовов между открытыми файлами.

## Что меняем (High-level)

Добавляем корректный межпроцедурный вывод return-типа для пользовательских функций/процедур:

1) **Контур конфигурации (persistent)**: при индексировании BSL-модулей конфигурации строим return‑summary для функций/процедур с учётом:
   - локальных (не export) вспомогательных функций внутри модуля;
   - вызовов между модулями (экспортных);
   - рекурсии/взаимной рекурсии через SCC + фикс‑пойнт.
   Результаты пишем в `SignatureIndex` как `return_type` для экспортных сигнатур (и location для навигации остаётся прежним).

2) **Overlay для IDE (in-memory)**: для набора открытых файлов вычисляем return‑summaries поверх загруженной конфигурации и используем их при резолве вызовов *между всеми открытыми файлами* без переиндексации всей конфигурации на диске.

3) **Семантика неопределённости**: если часть return’ов/веток не выводима, мы сохраняем известные типы и помечаем результат как слабый/динамический (`InferredWeak`), вместо деградации в “полный Unknown”.

## Границы (Non-goals)

- Полный CFG-based (flow-sensitive) межпроцедурный анализ для всех переменных. В рамках change делаем summary-based inference return-типа (достаточно для call-site типизации и сигнатур).
- Межпроектные/внешние зависимости за пределами загруженной конфигурации и открытых файлов.
- Попытки “угадать” вызов `F()` как глобальную функцию, если он неразличим с локальной (остаемся консервативными и помечаем неопределённость как weak).

## Влияние и совместимость (Impact)

- Улучшаются completion/hover/diagnostics для вызовов экспортных функций/процедур конфигурации и общих модулей.
- Поведение становится более детерминированным и устойчивым (фикс‑пойнт вместо разовых пост‑пасс патчей).
- Дисковый кэш парсинга модулей конфигурации может быть инвалидирован из‑за изменения формата сохранённых данных (ожидаемо).
