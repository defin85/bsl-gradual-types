КРИТИЧЕСКАЯ ПРОБЛЕМА
================================================================================

Функции find_call_context() и calculate_active_parameter() имеют bug в работе 
с byte индексами при многобайтных UTF-8 символах (кириллица):

Пример ошибки:
  Ожидалось: функция_название
  Получено:  функ (обрезано на середине символа)
  Причина: Смешивание byte indices и character indices

tower_lsp использует BYTE indices (tower_lsp::lsp_types::Position)
Но код работает как с CHARACTER indices
Результат: Panic на "byte index is not a char boundary"

================================================================================
ДЕТАЛИ ОШИБОК
================================================================================

Error: "byte index 7 is not a char boundary; it is inside 'к' (bytes 6..8)"

Причина:
  1. tower_lsp Position.character использует byte indices
  2. Код делает code[..byte_idx] без проверки char boundary
  3. Кириллические буквы = 2 байта в UTF-8
  4. Попытка обрезать на середине символа → Panic

Пример:
  Строка: "Функция("
  Position.character = 7 (по задумке это конец "Функ")
  Но на самом деле это byte 7 = середина буквы "ц"
  code[..7] → Panic: not a char boundary

   fn char_to_byte_index(s: &str, char_idx: u32) -> usize {
       s.chars()
           .take(char_idx as usize)
           .map(|c| c.len_utf8())
           .sum()
   }
   
   fn byte_to_char_index(s: &str, byte_idx: usize) -> u32 {
       s[..byte_idx].chars().count() as u32
