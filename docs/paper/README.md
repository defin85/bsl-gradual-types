# Научные основы BSL Gradual Types

## Основная статья

**Balyuk, A. S., & Popova, V. A. (2021).** *Static type-checking for programs developed on the platform 1C:Enterprise.* CEUR Workshop Proceedings, Vol-2984.

**URL:** https://ceur-ws.org/Vol-2984/paper13.pdf

## Краткое содержание

### Проблематика
- Язык 1С:Предприятие имеет динамическую типизацию
- Ошибки типов обнаруживаются только во время выполнения
- Отсутствуют инструменты статической проверки типов

### Решение авторов
1. **Configuration Types Tree (CTT)** — упрощённый XML-формат для описания типов
2. **Статический анализатор** на C++ с Flex + GNU Bison
3. Парсинг XML конфигураций для извлечения типовой информации

### Сложность типовой системы 1С

**Множественное наследование функциональности:**

Пример для `Справочники.Контрагенты`:
- `CatalogManager` — создание, поиск элементов
- `CatalogObject` — изменяемый объект
- `CatalogRef` — ссылка на элемент
- `CatalogSelection` — обход элементов
- `CatalogList` — управление списком в форме

### Категории обнаруженных ошибок

Тестирование на "1С:Библиотека стандартных подсистем" версии 3.1.3 выявило:

1. ❌ **Некорректная передача параметров методам**
   ```bsl
   // Ожидается: СтрЗаменить(<Строка>, <Строка>, <Строка>)
   // Передано: СтрЗаменить(<Строка>, <Число>, <Строка>)
   СтрЗаменить("текст", 123, "замена"); // ОШИБКА
   ```

2. ❌ **Обращение к несуществующим свойствам**
   ```bsl
   Справочник = Справочники.Контрагенты;
   Значение = Справочник.НесуществующееСвойство; // ОШИБКА
   ```

3. ❌ **Простые типы как коллекции**
   ```bsl
   Число = 42;
   Число.Добавить(10); // ОШИБКА: Число не является коллекцией
   ```

## Применение в BSL Gradual Types

### 1. Фасетная система (FacetKind)

**Файл:** [shared/src/domain/types.rs](../../shared/src/domain/types.rs)

```rust
pub enum FacetKind {
    Manager,     // СправочникМенеджер
    Object,      // СправочникОбъект
    Reference,   // СправочникСсылка
    Metadata,    // Метаданные
    Constructor, // Конструктор
    Collection,  // Коллекция
    Singleton,   // Одиночный объект
    Selection,   // СправочникВыборка ⭐ из статьи
    List,        // СправочникСписок ⭐ из статьи
}
```

### 2. Валидация типовых ошибок

**Файл:** [shared/src/domain/validators.rs](../../shared/src/domain/validators.rs)

```rust
pub enum TypeErrorKind {
    /// Некорректная передача параметров методу
    IncorrectParameterType { ... },

    /// Обращение к несуществующему свойству объекта
    NonExistentProperty { ... },

    /// Обработка простого типа как коллекции
    SimpleTypeAsCollection { ... },
}
```

**TypeValidator** реализует все три категории проверок из статьи.

### 3. Градуальная типизация

В отличие от чисто статического подхода Balyuk & Popova, наша система использует **градуальную типизацию**:

```rust
pub enum Certainty {
    Known,           // Точно известный тип
    Inferred(f32),   // Выведенный с уверенностью 0.0-1.0
    Unknown,         // Неизвестный тип (динамическая типизация)
}
```

**Ключевое отличие:** Неизвестные типы не вызывают ошибок компиляции, но генерируют предупреждения.

## Преимущества нашего подхода

| Аспект | Balyuk & Popova (2021) | BSL Gradual Types (2025) |
|--------|------------------------|--------------------------|
| Парсер | Flex/Bison (C++) | Tree-sitter (Rust) |
| Архитектура | Монолит | Right-Sized, модульная |
| Типизация | Статическая | **Градуальная** |
| UI | Отсутствует | Web (Leptos) + LSP |
| Интеграция | CLI | VSCode extension |
| Честность | Строгие ошибки | Градация уверенности |
