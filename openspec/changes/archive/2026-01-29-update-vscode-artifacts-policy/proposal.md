# Предложение изменений: Политика артефактов VS Code extension (`out/`, `*.vsix`) — не хранить в git

## Зачем
Сейчас в git присутствуют сгенерированные артефакты VS Code extension:
- `vscode-extension/out/**` (результат компиляции/сборки),
- `vscode-extension/*.vsix` (упакованные релизы).

Это создаёт техдолг:
- увеличивает размер репозитория и шум в diff;
- усложняет code review (генерированные файлы часто меняются массово);
- может маскировать реальные изменения исходников.

## Что меняется
- Зафиксировать политику: `out/` и `*.vsix` не версионируются в git.
- Обновить `.gitignore`/локальные игноры для extension.
- Обновить инструкции установки/релиза: как собрать и установить `.vsix` локально без хранения артефактов в репозитории.

## Не цели
- Изменение функциональности расширения.
- Автоматизация релиза в CI (это отдельный будущий change).

## Влияние
- Изменится состав файлов в git: из индекса будут удалены генерированные артефакты.
- Документация по установке будет опираться на сборку из исходников (или на внешние релизы, если появятся).

## Критерии готовности
- В git не отслеживаются `vscode-extension/out/**` и `vscode-extension/*.vsix`.
- В документации есть воспроизводимая инструкция сборки/упаковки и локальной установки.
