# ADR-001: Разделение функционала между клиентом и сервером

## Статус
Принято

## Контекст
Проект представляет собой семантическую инфраструктуру (Type / Semantic Inference Engine) для языка 1С (BSL), ориентированную прежде всего на машинное потребление (LLM, AI-агенты, CI), а не на человека.

Рассматривались различные способы поставки:
- standalone-бинарники (LSP / CLI / MCP у клиента);
- Docker / VM on-prem;
- централизованный сервер (SaaS / MCP as a Service).

Ключевые ограничения:
- защита интеллектуальной собственности;
- возможность usage-based pricing;
- контроль нагрузки от AI-агентов;
- масштабируемая unit economics;
- поддержка enterprise и regulated environments.

## Решение
Принято **server-first архитектурное решение** с чётким разделением ответственности.

### Сервер (source of truth)
На сервере **обязательно остаются**:
- Semantic / Type Inference Engine;
- фасетная модель типов;
- gradual typing и propagation;
- семантический граф и knowledge base;
- MCP / AI-facing API;
- логика лицензирования, квот, usage и SLA.

Сервер является:
- источником истины;
- носителем основной ценности продукта;
- точкой монетизации и контроля.

### Клиент (thin layer)
Клиентские компоненты:
- IDE / LSP расширения (thin);
- CLI / CI-адаптеры;
- on-prem VM / Docker как gateway (опционально).

Клиент:
- не содержит inference-логики;
- не является источником истины;
- используется только как интерфейс и интеграционный слой.

## Обоснование

### Почему не standalone
- невозможно контролировать usage;
- flat-rate экономика;
- утечка IP через бинарники;
- AI-tier не масштабируется.

### Почему не «зашифрованная VM»
- шифрование диска (LUKS / BitLocker) не защищает от владельца VM;
- ключи доступны в памяти;
- защита возможна только через TEE (SEV / SGX), что допустимо лишь для enterprise.

### Почему server-first
- позволяет usage-based pricing;
- поддерживает AI-first стратегию;
- защищает IP архитектурно, а не криптографически;
- повышает потолок цены;
- делает продукт инфраструктурным, а не утилитой.

## Последствия

### Положительные
- масштабируемая экономика;
- контроль нагрузки агентов;
- защита ключевого IP;
- возможность enterprise-контрактов;
- независимость от конкретных LLM.

### Отрицательные
- необходимость ops и SRE;
- требования к SLA;
- сложнее initial onboarding для on-prem клиентов.

## Примечания
- On-prem VM поддерживается только как enterprise-опция.
- Лицензирование on-prem реализуется через lease (временную аренду).
- Самый ценный код никогда не покидает сервер без контрактных и технических гарантий.

## Итог
Продукт позиционируется как **Semantic Infrastructure / Inference Platform**, где:
- сервер = продукт,
- клиент = адаптер,
- VM = deployment unit,
- LLM = пользователь.
