# Change: IDE-friendly rewrite/add правила для синтаксических ошибок (ParseError)

## Why
Сейчас синтаксические ошибки (tree-sitter `ERROR` nodes) конвертируются в диагностики почти напрямую:
сообщение вида `Синтаксическая ошибка: неожиданный текст '...'` и span, который часто попадает не в первопричину,
а в “первый токен, на котором парсер сломался”.

Это особенно заметно на частых ошибках, генерируемых LLM, например:
`Для Индекс = ... По 0 Шаг -1 Цикл` — в BSL нет клаузы `Шаг`, но текущая ошибка может подсветить `0`
или другой токен, не объясняя, что именно неверно и как исправить.

Цель — улучшить UX в LSP/IDE: при наличии `ParseError` выдавать более точные и полезные сообщения и spans
для распознаваемых паттернов, не меняя грамматику языка и не легализуя неверный синтаксис.

## What Changes
- Ввести слой “enhancers” для синтаксических ошибок:
  - правила двух типов: **rewrite** (заменяет/уточняет существующий `ParseError`) и **add** (добавляет новую диагностику);
  - правила запускаются **только если** в файле уже есть синтаксические ошибки (`ParseError`/`InvalidSyntax`/`MissingToken`).
- Политика по умолчанию: **rewrite-only**. Для одной строки с ошибкой система SHOULD возвращать **не более одной**
  синтаксической диагностики (приоритет — улучшенная, если правило сработало).
- Добавить встроенные правила (минимум v1 набора):
  - `Для`: узкое rewrite-правило для `Для ... По ... Шаг ... Цикл` (span указывает на `Шаг`, сообщение объясняет, что в BSL нет такого синтаксиса);
  - `Для`: обобщённое rewrite-правило для заголовка `Для` (класс ошибок “лишняя/неожиданная клауза между `По <expr>` и `Цикл`”);
  - `Если/Тогда`: rewrite-правило, улучшающее сообщение/span для частых ошибок заголовка `Если` (например, отсутствует `Тогда`,
    или заголовок завершён не тем токеном);
  - `Попытка/Исключение`: rewrite-правило, улучшающее сообщение/span для частых ошибок структуры блока `Попытка`
    (незакрытый блок, отсутствующий `Исключение`/`КонецПопытки`, и т.п.).
- Обеспечить детерминированность: одинаковый input → одинаковый набор diagnostics (message/type/span порядок).

## Impact
- Affected specs:
  - `bsl-intellisense-v2` (качество синтаксических diagnostics в IDE/LSP)
- Affected code (после утверждения и реализации):
  - `syntax/src/tree_sitter_adapter/*` (post-processing ParseError)
  - тесты `syntax/` (юнит-тесты на маленьких BSL-сниппетах)
  - опционально: `backend/src/bin/lsp_server/...` (если потребуется изменить mapping кода/категорий)

## Non-Goals
- Изменять/расширять грамматику `tree-sitter-bsl` так, чтобы “принять” неверный синтаксис.
- Делать полноценный “второй парсер”: enhancers работают как лёгкие эвристики/паттерны вокруг уже существующих ошибок.
- Добавлять CodeAction/quick-fix (можно отдельным change, если потребуется).
