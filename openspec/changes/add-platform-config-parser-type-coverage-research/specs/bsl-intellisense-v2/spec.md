## ADDED Requirements

### Requirement: v2 поддерживает воспроизводимый end-to-end аудит покрытия типов platform/config (MUST)
Система MUST предоставлять воспроизводимый аудит покрытия типов для pipeline platform/config type parsing с фиксацией стадий:
`source_discovered -> parser_extracted -> normalized -> indexed -> facet_projected -> lookup_resolvable`.

Аудит MUST формировать машиночитаемый артефакт, который позволяет сопоставить статус каждого типа по всем стадиям.

#### Scenario: Аудит строит stage-based матрицу покрытия
- **GIVEN** загружены platform source и configuration metadata
- **WHEN** выполняется запуск аудита покрытия типов
- **THEN** система формирует артефакт, где для каждого типа зафиксирован статус на каждой стадии lifecycle
- **AND** артефакт детерминирован при повторном запуске на том же входном snapshot

### Requirement: Нерезолвленные типы не теряются "молча" и имеют root-cause классификацию (MUST)
Если тип не проходит хотя бы одну стадию lifecycle, система MUST фиксировать gap с полями:
- `first_failed_stage`,
- `reason_code`,
- диагностический контекст (`source`, `normalized_name`, дополнительные детали).

Система MUST включать baseline-кейс `БиблиотекаКартинок` в отчёт исследования как минимум до момента, пока он не будет полностью резолвиться.

#### Scenario: `БиблиотекаКартинок` отражается в отчёте как gap до устранения причины
- **GIVEN** в текущем состоянии pipeline тип `БиблиотекаКартинок` не резолвится end-to-end
- **WHEN** выполняется аудит покрытия типов
- **THEN** отчёт содержит запись по `БиблиотекаКартинок` с `first_failed_stage` и `reason_code`
- **AND** запись позволяет локализовать подсистему, где возникла потеря типа

### Requirement: Аудит покрытия типов учитывает фасеты и контексты модулей (MUST)
Аудит MUST проверять доступность типов не только на уровне "тип существует", но и на уровне фасетов/контекстов, используемых IDE.

Минимально MUST быть покрыты фасеты:
- `Менеджер`
- `Объект`
- `Ссылка`
- `Список`
- `Выборка`

Для form-context сценариев MUST быть отдельная проверка на применимость типа в `FormModule.Объект`.

#### Scenario: Type-level успех и facet-level провал различаются в отчёте
- **GIVEN** тип присутствует в `TypeRepository`, но недоступен в одном из ожидаемых фасетов
- **WHEN** выполняется аудит покрытия типов
- **THEN** отчёт фиксирует type-level успех и facet-level gap как разные статусы
- **AND** указывает проблемный фасет/контекст для последующего исправления
