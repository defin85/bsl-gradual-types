## Observed Runtime Shape

- Same-version `didSave` rebuild now reuses current-state exact-safe seeds only for actual
  same-text rebuilds (`parser_edits.is_empty()`), avoiding the stale-proof leak into promoted
  `didChange` workers.
- Same-content exact ready-snapshot assembly now uses a bounded lowering reuse plan derived from
  cached AST state instead of reporting `FullRebuild` on unchanged content.
- Same-content exact reuse no longer lets a same-version reprime clobber an existing owned AST
  cache entry: the new synthetic repro proves the exact path can now stay on
  `reuse_plan_take_if_unique=true` after reprime instead of degrading to a borrowed-clone reuse
  plan.
- The preserved same-version in-flight follow-up shape is now truthful as
  `followup_semantic_path=detached_ready_artifacts`,
  `followup_ready_snapshot_wait_probe=not_ready`, and
  `followup_ready_snapshot_bounded_wait_winner=detached_ready_artifacts`.
- Delayed same-version `didChange` post-handoff no longer needs to win the save cycle in order for
  `didSave` follow-up to wait on exact work: the current-save-cycle `DidSave` worker is now
  classified as `in_flight_same_version`, and stale same-version `didChange` diagnostics
  scheduling is guarded by the observed `save_cycle_sequence`.
- Diagnostics-save fastlane first-publish proof no longer disappears when the active cycle is
  archived: `wait_for_save_fastlane_first_publish_v2` now falls back to matching timeline traces
  keyed by `(uri, requested_version, diagnostics_generation, save_cycle_sequence)`, and the new
  archived-trace regression is green.
- In-flight exact-worker phase snapshots now keep `program_lowering_summary` as well: the
  background parse task control stores the summary once `build_parse_snapshot_v2` returns, and
  `DiagnosticsReadySnapshotPhaseAttributionV2::from_snapshot()` now exports the same
  `program_lowering_reuse_*` family that the completed ready-state path already exposed.
