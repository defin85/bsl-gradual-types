# Design: LLM-friendly MCP inputs for `bsl-agent`

## Цели
- Дать LLM максимально простой, повторяемый формат ввода (в первую очередь: абсолютные пути и строковые scope), не ломая существующие DTO.
- Обеспечить детерминизм и безопасность (sandbox по roots) для multi-root.
- Устранить “магическое” поведение вокруг `configuration_path`/`platform_version` (fail-fast + автоматизация).

## Нормализация путей (multi-root)
Везде, где принимаются `DocumentRef`/`FileRef`/`WorkspaceScope::File`, добавляется поддержка абсолютного пути как альтернативы каноническому `{root_id, relative_path}`.

Правила:
- Сервер канонизирует абсолютный путь (best-effort canonicalize) и проверяет, что он находится внутри одного из `roots[]`.
- Root выбирается детерминированно: **longest-prefix match** по каноническим путям roots.
- Если путь вне всех roots — `INVALID_PARAMS`.
- Если roots пересекаются, longest-prefix остаётся детерминированным (более специфичный root побеждает).

Результат нормализации: `(root_id, relative_path)` с `relative_path` в POSIX-форме (`/`), без `..`, без абсолютных компонентов.

## Инференс `platform_version` из дампа конфигурации
Если пользователь передал `configuration_path`, но не передал `platform_version`, сервер:

1) Пытается извлечь режим совместимости/версию платформы из `Configuration.xml` в корне дампа.
2) Маппит значение на строку версии в формате, совместимом с backend (например, `8.3.25`).
3) Если определить не удалось — возвращает `INVALID_PARAMS` с сообщением, что нужно указать `platform_version` вручную.

Примечание: это не “fallback” с изменением поведения; это автоматизация, позволяющая LLM не заниматься парсингом конфигурации самостоятельно.

## Прогресс
Семантика `progress.percent`:
- `0..99` — job ещё выполняется;
- `100` — job в terminal-состоянии и результат (если успешен) готов к чтению через `job_result`.
