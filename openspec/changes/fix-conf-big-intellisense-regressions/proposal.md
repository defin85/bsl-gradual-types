# Change: fix-conf-big-intellisense-regressions

## Why
На больших конфигурациях (`examples/conf_big`) заметны регрессии/дыры IDE‑опыта:

1) **Format on Save** спамит ошибками LSP:
`textDocument/formatting failed: Invalid request (-32600)`.
Это ломает UX и скрывает реальные проблемы.

2) **Ложная диагностика “необъявленная переменная”** для локальной функции модуля формы,
вызванной до объявления:
`СписокВидимыхТабличныхЧастей()` используется на `.../Module.bsl#L23`, объявлена на `.../Module.bsl#L3635`,
но диагностика считает это переменной.

3) **Go to Definition не работает по конфигурационным модулям**, даже когда определение существует:
пример: `РеализацияТоваровУслугФормы.ПриСозданииНаСервере(...)` в
`examples/conf_big/Documents/РеализацияТоваровУслуг/Forms/ФормаДокументаОбщая/Ext/Form/Module.bsl#L19`
должно вести в `examples/conf_big/CommonModules/РеализацияТоваровУслугФормы/Ext/Module.bsl#L11`, но “не найдено”.

4) **Типы реквизитов формы и элементов формы не резолвятся**:
в модуле формы `СчетФактура` и `Элементы.СчетФактураПросмотр` должны резолвиться по `Form.xml`,
но hover/diagnostics показывают unknown/“property not exists”.

## What Changes
- Исправить контракт форматирования: если форматирование выключено — сервер не заявляет capability и не возвращает `-32600`.
- Обеспечить hoisting/видимость локальных процедур/функций модуля для инференса/валидации (в т.ч. вызов до объявления).
- Добавить навигацию definition по конфигурационным common modules (и их экспортируемым процедурам/функциям) по метаданным.
- Подключить реквизиты формы и элементы формы из `Form.xml` в типовую модель:
  - `Элементы` содержит реальные элементы (в т.ч. `UsualGroup`),
  - реквизиты формы (`<Attribute ...>`) доступны как идентификаторы в модуле формы.

## Impact
- Спецификации: delta для `bsl-intellisense-ide-grade`.
- Код (apply‑стадия): LSP server (formatting + definition), semantic/type inference, config form metadata parser/type repository integration.
- Тесты: регресс‑тесты на `conf_big` (минимальные, детерминированные).

## Scope (MVP)
Фокус на конкретных воспроизводимых кейсах из `examples/conf_big`, без попытки “закрыть всё сразу”:
- formatting: убрать `-32600` и корректно гейтить capability;
- local function call: не выдавать “undeclared variable” на вызов локальной функции;
- definition: минимум для `CommonModules.<Name>.<ExportProc>` и `CommonModules.<Name>` (как namespace);
- forms: подмешать реквизиты/элементы формы в типовую модель для property access и hover.

## Non-goals
- Полная реализация форматтера/стиля (только корректный контракт + отсутствие спама ошибок).
- Полный кросс‑модульный rename/references по конфигурации.
- Полная типизация всех возможных UI‑элементов формы (покрываем необходимые виды, расширяем по мере нужды).
