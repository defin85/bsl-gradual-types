## 1. Proposal / Specs

- [x] 1.2 `openspec validate add-syntax-diagnostics-rewrite-rules --strict --no-interactive`.

## 2. Implementation (syntax)
- [x] 2.1 Ввести API/каркас для “enhancers” синтаксических ошибок (rule interface + pipeline), без изменения грамматики.
- [x] 2.2 Подключить pipeline в `TreeSitterAdapter::convert_tree` после `collect_syntax_errors_cached` и перед возвратом `ParseResult`.
- [x] 2.3 Реализовать политику rewrite-only: не более 1 синтаксической диагностики на строку с ошибкой (приоритет — улучшенная).
- [x] 2.4 Реализовать узкое rewrite-правило `Для`: `Для ... По ... Шаг ... Цикл` → `InvalidSyntax` со span на `Шаг` и объясняющим сообщением.
- [x] 2.5 Реализовать обобщённое rewrite-правило `Для`: улучшить сообщение/span для “неожиданной клаузы” в позиции между `По <expr>` и `Цикл`.
- [x] 2.6 Реализовать rewrite-правило `Если/Тогда`: улучшить сообщение/span для частых ошибок заголовка `Если` (например, отсутствует `Тогда`).
- [x] 2.7 Реализовать rewrite-правило `Попытка/Исключение`: улучшить сообщение/span для частых ошибок структуры блока `Попытка`.

## 3. Tests
- [x] 3.1 Юнит‑тест: `Для ... По 0 Шаг -1 Цикл` выдаёт диагностику, указывающую на `Шаг`, а не на `0`.
