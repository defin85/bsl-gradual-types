# Change: Лексическая видимость локальных символов в non-member completion v2

## Why
Сейчас non-member completion получает локальные символы из файлового `symbol_index`, из-за чего подсказки могут включать:
- локальные переменные из нерелевантных блоков/процедур,
- символы, объявленные после позиции курсора,
- дубли и неверные кандидаты при затенении имён.

Это снижает релевантность completion и делает поведение менее предсказуемым в реальном IDE-сценарии.

## What Changes
- Добавляется v2-сборщик локальных кандидатов completion из IR snapshot по позиции курсора (scope-aware).
- Для non-member completion вводится контракт видимости локалов:
  - видны только символы из лексической области, содержащей позицию;
  - символы после позиции курсора не предлагаются;
  - при затенении побеждает ближайшее объявление;
  - неявные локалы (`x = ...`) становятся видимыми с точки присваивания.
- Источником локальных символов становится v2 snapshot текущей ревизии документа; файловый индекс используется для module/global/meta/keywords.
- Добавляются регрессионные и интеграционные тесты на видимость по блоку/позиции.

## Impact
- Затрагиваемые спецификации: `bsl-intellisense-v2`.
- Затрагиваемые подсистемы (ожидаемо): `bsl-runtime` completion pipeline, `analysis-v2`/`shared` (reuse scope-position helpers), integration/golden tests LSP completion.
- Совместимость: поведение completion станет строже и релевантнее; часть ранее показываемых локалов (нерелевантных по блоку/позиции) перестанет предлагаться.

## Non-Goals
- Не меняется member-access completion (`expr.`) и логика вывода members по типу receiver.
- Не меняется контракт LSP `completionItem/resolve`.
- Не добавляются новые публичные API/CLI команды.
