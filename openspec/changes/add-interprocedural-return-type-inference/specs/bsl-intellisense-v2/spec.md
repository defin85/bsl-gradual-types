## ADDED Requirements

### Requirement: Межфайловый вывод return‑типа пользовательских экспортов конфигурации (MUST)
Система MUST выводить возвращаемый тип пользовательских функций конфигурации, доступных через `SignatureIndex`:
- для экспортных функций/процедур общих модулей и объектных модулей конфигурации;
- с учётом вызовов между модулями конфигурации;
- с учётом локальных (не export) вспомогательных функций внутри модуля, если они влияют на return экспортной функции;
- с корректной обработкой рекурсии/взаимной рекурсии (фикс‑пойнт до стабилизации).

#### Scenario: Экспортная функция возвращает значение через локальный helper
- **GIVEN** экспортная функция `F()` возвращает результат локальной функции `H()`, объявленной в том же модуле
- **AND** `H()` возвращает значение выводимого типа (например, `Строка` или `Число`)
- **WHEN** другой модуль вызывает `F()`
- **THEN** call site получает тип, совместимый с выведенным возвращаемым типом `F()` (без деградации в “всегда Unknown”)

### Requirement: Overlay return‑summaries для всех открытых файлов (MUST)
Система MUST поддерживать overlay‑слой поверх загруженной конфигурации для несохранённых изменений в IDE:
- изменения в одном открытом файле MUST влиять на результаты типизации вызовов в других открытых файлах, если между ними есть вызовы пользовательских экспортов;
- overlay MUST работать без переиндексации всей конфигурации на диске.

#### Scenario: Правка return в одном открытом файле влияет на типы вызовов в другом
- **GIVEN** в IDE открыты два файла A и B, и A вызывает экспортную функцию из B
- **WHEN** пользователь меняет тело функции в B так, что её возвращаемый тип меняется
- **THEN** completion/hover/type-at-position в A используют обновлённый возвращаемый тип (из overlay), без ожидания полной переиндексации конфигурации

### Requirement: Не терять известные типы при неопределённости return inference (MUST)
Если return‑inference сталкивается с неопределённостью (неразрешимый вызов, динамика, неоднозначность), система MUST:
- сохранять уже известные варианты типов (union), если они были выведены;
- помечать результат как слабый/динамический (например, через `Certainty::InferredWeak` на уровне `TypeResolution`), а не заменять известный union на “полный Unknown”.

#### Scenario: Динамика не уничтожает известную часть union
- **GIVEN** функция возвращает `Строка` в одной ветке и результат динамического/неразрешимого выражения в другой ветке
- **WHEN** система строит возвращаемый тип функции
- **THEN** результат содержит `Строка` как известный вариант и помечен как слабый/неопределённый, а не превращён в “Unknown без вариантов”

### Requirement: Использование существующих кэшей без блокирующего I/O в hot path (MUST)
Система MUST использовать существующие кэши и не добавлять блокирующий I/O в hot path IDE‑запросов:
- кэширование парсинга/индексации конфигурационных модулей — через существующий DiskCache;
- overlay для открытых файлов — через v2 snapshot/queries (salsa) без чтения файлов с диска в ответ на hover/completion/signatureHelp/diagnostics.

#### Scenario: Повторные IDE‑запросы не триггерят чтение конфигурации с диска
- **GIVEN** конфигурация загружена и индексы построены
- **WHEN** IDE многократно делает hover/completion в открытых файлах
- **THEN** система использует кэши и snapshot’ы и не выполняет блокирующее чтение/сканирование конфигурации с диска в рамках этих запросов
