Отлично, вот практичный UI-чек-лист “открыл модуль в расширении и проверил”.

  Smoke-чеклист (Go/No-Go)

  1. Откройте модуль формы: Documents/Док1/Forms/Форма1/Ext/Form/Module.bsl
     Вставьте:

  Процедура Тест()
      Этот
      Пар
      Объект.
  КонецПроцедуры

  Проверьте:

  - на Этот есть ЭтотОбъект
  - на Пар есть Параметры
  - на Объект. есть Ссылка и ПометкаУдаления
  - на Объект. есть хотя бы один метод (например Записать)

  2. В том же модуле формы проверьте *БезКонтекста
     Вставьте:

  &НаСервереБезКонтекста
  Процедура Тест()
      Этот
      Пар
  КонецПроцедуры

  Проверьте:

  - нет ЭтотОбъект
  - нет Объект
  - нет Параметры

  3. Откройте менеджер модуля: Documents/Док1/Ext/ManagerModule.bsl
     Вставьте:

  Процедура Тест()
      Этот
      Об
  КонецПроцедуры

  Проверьте:

  - на Этот есть ЭтотОбъект
  - на Об есть Объект

  4. Откройте объектный модуль: Documents/Док1/Ext/ObjectModule.bsl
     Тот же код, проверьте:

  - на Этот есть ЭтотОбъект
  - на Об есть Объект

  5. Откройте модуль набора записей: InformationRegisters/Регистр1/Ext/RecordSetModule.bsl
     Тот же код, проверьте:

  - на Этот есть ЭтотОбъект
  - на Об есть Объект

  6. Проверка “completion → diagnostics consistency” в форме
     В модуле формы выберите любой member из Объект. (лучше Ссылка) и вставьте:

  Процедура Тест()
      Проверка = Объект.Ссылка;
  КонецПроцедуры

  Проверьте:

  - нет ложной ошибки вида Свойство/Метод ... не существует для выбранного member.

  7. Hover/тип не должен светить legacy/internal имена
     Наведите hover на Объект в модуле формы и на completion item detail/documentation.
     Проверьте:

  - нет ДанныеФормыОбъект
  - нет contextual:

  8. Стабильность выдачи
     На одном и том же месте (например Объект.) вызовите completion 3-5 раз подряд.
     Проверьте:

  - порядок верхних подсказок не “прыгает”.

  Если пункты 1-8 проходят, это Go для архивирования change (после формального закрытия review/latency пунктов в tasks.md).
