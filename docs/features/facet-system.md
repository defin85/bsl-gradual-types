# Фасетная система типов BSL

## Введение

Фасетная система типов - это подход к типизации метаданных 1С, где один объект конфигурации имеет множество представлений (фасетов).

**Научная основа:** Balyuk & Popova (2021) - "Type System for 1C:Enterprise Platform"

## Что такое фасеты?

Один справочник имеет 5 фасетов:

| Фасет | Тип | Назначение | Как получить |
|-------|-----|------------|--------------|
| Manager | СправочникМенеджер | Создание, поиск | `Справочники.Контрагенты` |
| Object | СправочникОбъект | Изменяемый объект | `.СоздатьЭлемент()` |
| Reference | СправочникСсылка | Ссылка на элемент | `.НайтиПоКоду()` |
| Selection | СправочникВыборка | Обход элементов | `.Выбрать()` |
| List | СправочникСписок | UI представление | Для форм |

## Примеры использования

### Manager facet

```bsl
// PropertyAccess → Manager facet
М = Справочники.Контрагенты;
// Тип: СправочникМенеджер.Контрагенты

// Доступные методы:
// - СоздатьЭлемент() → Object (ServerOnly)
// - НайтиПоКоду(Код) → Reference (ServerOnly)
// - Выбрать() → Selection (ServerOnly)
// - ПустаяСсылка() → Reference (Universal)
```

### Object facet

```bsl
// Метод СоздатьЭлемент() переключает на Object facet
Объект = М.СоздатьЭлемент();
// Тип: СправочникОбъект.Контрагенты

Объект.Наименование = "ООО Рога и Копыта";
Объект.Записать();
```

### Reference facet

```bsl
// Метод НайтиПоКоду() переключает на Reference facet
Ссылка = М.НайтиПоКоду("000001");
// Тип: СправочникСсылка.Контрагенты

Наименование = Ссылка.Наименование;
```

### Selection facet

```bsl
// Метод Выбрать() переключает на Selection facet
Выборка = М.Выбрать();
// Тип: СправочникВыборка.Контрагенты

Пока Выборка.Следующий() Цикл
    Сообщить(Выборка.Наименование);
КонецЦикла;
```

## Серверный/Клиентский контекст

Методы имеют требования к контексту выполнения:

| Контекст | Директива | Доступные методы |
|----------|-----------|------------------|
| ServerOnly | &НаСервере | СоздатьЭлемент, НайтиПоКоду, Выбрать, Записать |
| ClientOnly | &НаКлиенте | (специфичные клиентские) |
| Universal | Везде | ПустаяСсылка, Пустая, метаданные |
| ServerPreferred | Предпочтительно сервер | Оптимизированные методы |

### Пример: Context validation

```bsl
&НаКлиенте
Процедура КлиентскийМетод()
    // ⚠️ WARNING: НайтиПоКоду недоступен в клиентском контексте
    // Будет показана диагностика с WARNING severity
    Ссылка = Справочники.Контрагенты.НайтиПоКоду("001");
КонецПроцедуры

&НаСервере
Процедура СерверныйМетод()
    // ✅ OK: НайтиПоКоду доступен на сервере
    Ссылка = Справочники.Контрагенты.НайтиПоКоду("001");
КонецПроцедуры
```

LSP покажет **Warning** (не Error!) с подсказкой для клиентского кода:

```
⚠️ WARNING: Method 'НайтиПоКоду' requires ServerOnly context, but called in ClientOnly context

Hint: Move this call to &НаСервере function or use server call (e.g., НаСервереБезКонтекста)
```

## Hover информация в VSCode

При наведении на переменную VSCode показывает (с настройкой `detailLevel: "detailed"`):

```
Переменная: СправочникКонтрагенты
Тип: СправочникМенеджер.Контрагенты
Фасет: Менеджер (создание, поиск элементов)
💡 Доступные фасеты: Менеджер, Объект, Ссылка, Выборка, Список

Методы (показано 4 из 4):
• СоздатьЭлемент() → СправочникОбъект.Контрагенты (🖥️ Server)
• НайтиПоКоду(Код: Строка) → СправочникСсылка.Контрагенты (🖥️ Server)
• Выбрать() → СправочникВыборка.Контрагенты (🖥️ Server)
• ПустаяСсылка() → СправочникСсылка.Контрагенты (🌐 Universal)
```

### Context badges

- 🖥️ **Server** - метод доступен только на сервере (&НаСервере)
- 💻 **Client** - метод доступен только на клиенте (&НаКлиенте)
- 🌐 **Universal** - метод доступен везде
- ⚡ **Server Preferred** - предпочтительно на сервере (для оптимизации)

## Реализация

### Milestone 3.11: Context-Aware Facet Selection

Фасетная система реализована в 4 фазы:

**Phase 1: Data structures** (✅ Завершено)
- `ContextRequirements` enum в `TypeResolution`
- `return_facet` в `MethodSignature`

**Phase 2: Execution context** (✅ Завершено)
- `ExecutionContext` с tracking директив компиляции
- Парсинг `&НаСервере` / `&НаКлиенте`
- Facet switching на основе `return_facet`

**Phase 3: Context validation** (✅ Завершено)
- Валидация вызовов методов с учётом контекста
- LSP diagnostics с WARNING severity
- 20+ integration тестов

**Phase 4: VSCode UX improvements** (✅ Завершено)
- Hover показывает активный фасет и описание
- Context badges (🖥️ Server, 💻 Client, 🌐 Universal)
- Доступные фасеты в hover
- 12 unit тестов

## Научная основа

Balyuk, A., & Popova, E. (2021). "Type System for 1C:Enterprise Platform"

**Ключевые концепции:**

1. **Faceted Type Representation** - множественные представления одного метаданного объекта
2. **Context-Dependent Method Resolution** - методы зависят от контекста выполнения (сервер/клиент)
3. **Dynamic Facet Switching** - переключение фасетов через вызовы методов

**Цитата (стр. 6):**

> "Metadata objects in 1C platform have multiple type representations (facets): Manager, Object, Reference, Selection, and List. Each facet provides specific set of operations suitable for the context."

## Примеры из реальных проектов

### Пример 1: Создание и сохранение элемента

```bsl
&НаСервере
Процедура СоздатьКонтрагента(Наименование)
    // Manager facet
    М = Справочники.Контрагенты; // Type: СправочникМенеджер

    // Manager → Object (через СоздатьЭлемент)
    Объект = М.СоздатьЭлемент(); // Type: СправочникОбъект
    Объект.Наименование = Наименование;

    // Object → Reference (через Записать)
    Ссылка = Объект.Записать(); // Type: СправочникСсылка

    Возврат Ссылка;
КонецПроцедуры
```

### Пример 2: Поиск и обработка элементов

```bsl
&НаСервере
Процедура ОбработатьКонтрагентов()
    // Manager facet
    М = Справочники.Контрагенты;

    // Manager → Selection (через Выбрать)
    Выборка = М.Выбрать(); // Type: СправочникВыборка

    Пока Выборка.Следующий() Цикл
        // Selection → Reference (через Ссылка)
        Ссылка = Выборка.Ссылка; // Type: СправочникСсылка

        // Reference → Object (через ПолучитьОбъект)
        Объект = Ссылка.ПолучитьОбъект(); // Type: СправочникОбъект
        Объект.Комментарий = "Обработан";
        Объект.Записать();
    КонецЦикла;
КонецПроцедуры
```

### Пример 3: Клиент-серверное взаимодействие

```bsl
&НаКлиенте
Процедура КлиентскийКод()

    ПустаяСсылка = Справочники.Контрагенты.ПустаяСсылка();

    // ⚠️ WARNING: НайтиПоКоду требует ServerOnly контекст
    // Ссылка = Справочники.Контрагенты.НайтиПоКоду("001");

    // Правильный подход - серверный вызов
```

## FAQ

### Q: Почему валидация context показывает WARNING, а не ERROR?

**A:** Это прагматичное решение. В 1С возможны легитимные случаи вызова серверных методов на клиенте через server calls (`НаСервереБезКонтекста`). WARNING предупреждает разработчика, но не блокирует код.

### Q: Как отключить показ фасетов в hover?

**A:** Используйте настройку `detailLevel: "full"` или `"compact"` вместо `"detailed"`.

### Q: Можно ли добавить свои context requirements?

**A:** Да, расширьте enum `ContextRequirements` в `shared/src/domain/runtime_context.rs`. Например, для mobile-specific context.

### Q: Поддерживается ли фасетная система для Документов, Регистров?

**A:** Частично. Справочники поддерживаются полностью. Документы и Регистры - в разработке (см. Milestone 3.12).

### Q: Как добавить context_requirements для custom типов?

**A:** Расширьте `RawMethodData` в `platform_types.rs` или через Configuration Loader (Milestone 3.12).
