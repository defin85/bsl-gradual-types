# Change: update-bsl-agent-tool-descriptions

## Why
`bsl-agent` используется MCP‑клиентами как “инструментальный” сервер. Для надёжного использования (в т.ч. LLM‑агентами поверх MCP) описания tool-ов должны быть **однозначными**: особенно там, где есть выбор формата (пути/roots, scope, позиция) и где ошибки иначе выглядят как “рандом”.

Сейчас описания tool-ов в `tools/list` в основном короткие, но:
- не фиксируют ключевые форматы и правила (multi-root, абсолютные пути, scope);
- вынуждают клиентов “угадывать” правильные payload’ы или лезть в внешнюю документацию;
- если вшивать примеры прямо в каждое описание, резко растёт объём `tools/list` (токены), что плохо для LLM-кейсов.

## What Changes
- Обновить `description` у ключевых tool-ов так, чтобы они были **короткими**, но снимали неоднозначности (форматы и правила — в 1 строку).
- Ввести единый стиль описаний (структура, ключевые слова, максимум длины).
- Добавить отдельный read-only tool для on-demand справки/примеров (например, `mcp_help` или `tool_examples`), чтобы **не раздувать** `tools/list`, но дать клиенту канонические примеры вызовов.
- Добавить/уточнить требования в спецификации `mcp-bsl-agent` про качество и минимальность описаний tool-ов и про on-demand help.

## Impact
- Спецификация: `openspec/specs/mcp-bsl-agent/spec.md`
- Код: `bsl-agent` (только тексты `#[tool(description=...)]`, плюс новый read-only tool для справки)
- Документация: при необходимости короткая ссылка на `docs/roadmap/mcp-bsl-agent/api.md` как “полный контракт”

## Non-goals
- Не менять семантику tool-ов и DTO (только описание + отдельный help tool).
- Не дублировать большие примеры во всех `description`.
