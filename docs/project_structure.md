# Структура Проекта "BSL Gradual Type System"

## 1. Обзор Архитектуры

Проект представляет собой **full-stack монорепозиторий на Rust**, построенный по архитектуре **"Ядро и Адаптеры"**. Он использует **"плоское" рабочее пространство (flat workspace)**, где каждый основной компонент является отдельным крейтом (папкой) в корневой директории. **Корневой папки `src` нет.**

-   **Ядро (`shared`)**: Содержит всю чистую бизнес-логику.
-   **Адаптеры (`backend`, `frontend`, `cli`)**: Предоставляют различные интерфейсы для взаимодействия с ядром.

---

## 2. Файлы в Корневой Директории

-   `Cargo.toml`: **Манифест рабочего пространства (workspace).** Определяет, какие папки (`backend`, `frontend`, `shared` и т.д.) являются членами монорепозитория.
-   `Cargo.lock`: Файл, который фиксирует точные версии всех зависимостей проекта для обеспечения воспроизводимости сборок.
-   `README.md`: Главный описательный файл проекта.
-   `.gitignore`: Стандартный файл для исключения из контроля версий артефактов сборки (`target/`), кэша и локальных конфигураций.
-   `build.rs`: Скрипт сборки Rust. Может использоваться для кодогенерации или компиляции зависимостей не на Rust.
-   `.mcp.json`, `.trae`, `.claude`, `CLAUDE.md`, `GEMINI.md`: Конфигурационные файлы и документация, связанные с интеграцией со сторонними сервисами и AI-моделями.

## 3. Основные Крейты (Компоненты)

### 🧠 `shared/` — Ядро Приложения (Domain + API)

**Роль:** Независимая библиотека, содержащая всю бизнес-логику. Не имеет зависимостей от веб-серверов, UI или файловой системы.

-   `Cargo.toml`: Манифест крейта `shared`.
-   `src/lib.rs`: Точка входа в библиотеку, которая собирает и экспортирует все публичные модули.
-   `src/domain/`: **Чистый доменный слой.** Содержит ядро логики.
    -   `analysis/`: Алгоритмы анализа кода.
        -   `type_checker.rs`: **Главный компонент.** Реализует `TypeResolver` — логику проверки типов, flow-sensitive анализ и работу со взвешенными типами.
        -   `type_checker_simple.rs`: ⚠️ **Роль неясна.** Возможно, устаревший или упрощенный алгоритм.
    -   `repository.rs`: Определяет `trait TypeRepository` — интерфейс для получения данных (например, из конфигурационных файлов 1С), абстрагируя ядро от способа их хранения.
    -   `types.rs`: Определяет ключевые доменные сущности (`TypeResolution`, `WeightedUnionType` и т.д.).
    -   `standard_types.rs`: Определяет встроенные, стандартные типы языка BSL.
-   `src/api/`: **Контракт приложения.** ⚠️ **В зачаточном состоянии.** Предназначен для определения структур данных (DTO), используемых для обмена между `backend` и `frontend`.
-   `src/types/`: **Общие типы.** ⚠️ **В зачаточном состоянии.** Предназначен для базовых, переиспользуемых типов данных.

### ⚙️ `backend/` — Серверный Адаптер

**Роль:** Серверное приложение, которое предоставляет HTTP API и LSP для доступа к ядру. Реализует слои `System`, `Application`, `Data` и `Presentation`.

-   `config.toml`: Конфигурационный файл сервера (порты, уровни логирования и т.д.).
-   `src/main.rs`: Точка входа в приложение, запускает сервер и все компоненты.
-   `src/system/`: **Системный слой.**
    -   `system_coordinator.rs`: "Оркестратор", который управляет жизненным циклом и зависимостями всех компонентов.
    -   `analysis_cache.rs`: Реализация кэширования результатов анализа.
    -   `parser_coordinator.rs`: Управляет процессом парсинга исходного кода.
-   `src/application/`: **Прикладной слой.**
    -   `type_system_service.rs`: Реализует `TypeSystemService`, предоставляя высокоуровневые бизнес-операции (например, "проверить файл").
-   `src/data/`: **Слой данных.**
    -   `loaders/`: Конкретные реализации `TypeRepository` для загрузки XML-конфигураций 1С и других данных.
-   `src/presentation/`: **Презентационный слой (серверная часть).**
    -   `web/`: Реализация `Web Interface`. Содержит `router.rs` для определения HTTP-маршрутов и `handlers.rs` для их обработки.
    -   `lsp/`: Реализация `LSP Server` для интеграции с VS Code (подсказки, действия в коде и т.д.).
    -   `cli/`: ⚠️ **Устарел.** Артефакт рефакторинга, который следует удалить.
-   `src/bin/`: Исполняемые бинарные файлы.
    -   `lsp_server.rs`: Запускает Language Server Protocol как отдельный процесс.

### 🌐 `frontend/` — Адаптер для Веб-интерфейса

**Роль:** Клиентское SPA-приложение на Rust/WASM для визуализации результатов анализа.

-   `Trunk.toml`: Конфигурация для `Trunk` — сборщика Rust/WASM приложений.
-   `index.html`: HTML-файл-"оболочка" для загрузки SPA.
-   `src/lib.rs`: Точка входа в frontend-приложение, определяет корневой компонент и маршрутизацию.
-   `src/pages/`: Основные "экраны" или страницы приложения (`dashboard.rs`, `graph.rs` и т.д.).
-   `src/components/`: Переиспользуемые UI-элементы (кнопки, графики, таблицы), из которых строятся страницы.
-   `src/api/`: Клиентская часть для взаимодействия с `backend`.
    -   `client.rs`: HTTP-клиент для отправки запросов на сервер.
    -   `types.rs`: Rust-структуры, соответствующие DTO из `shared/api/`, для безопасной десериализации ответов.

### 💻 `cli/` — Адаптер для Командной Строки

**Роль:** Утилита для запуска анализа из консоли. Идеально подходит для CI/CD и скриптов.

-   `src/main.rs`: Точка входа, отвечает за парсинг аргументов командной строки (например, с помощью `clap`).
-   `src/lib.rs`: Основная логика CLI, отделенная для возможности тестирования.
-   `src/commands/`: ⚠️ **Не реализован.** Папка-заготовка для реализации подкоманд (`check`, `stats` и т.д.).

### 🔌 `vscode-extension/` — Адаптер для VS Code

**Роль:** Расширение для Visual Studio Code, написанное на TypeScript. Обеспечивает глубокую интеграцию с редактором.

-   `package.json`: Манифест Node.js, определяет зависимости и метаданные расширения.
-   `src/extension.ts`: Главный файл расширения, активирует и координирует его функционал (например, запуск LSP-клиента).

## 4. Вспомогательные Директории

-   `docs/`: Проектная и архитектурная документация, включая `simplified_architecture.md`.
-   `tests/`: Интеграционные тесты для всего рабочего пространства.
-   `benches/`: Тесты производительности (бенчмарки).
-   `examples/`: Примеры использования библиотеки или CLI.
-   `.github/`: Конфигурации для GitHub, в основном для CI/CD (GitHub Actions).
-   `target/`: Директория, создаваемая компилятором Rust. Содержит все артефакты сборки. Исключена из Git.
