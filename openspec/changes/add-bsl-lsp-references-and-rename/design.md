# Design: LSP references + rename for BSL

## Цель
Дать IDE базовую навигацию по использованиям символов и безопасное переименование на тех конструкциях, где статический анализ даёт достаточно уверенности.

## Подход (минимальный, но корректный)
- Опора на IR/семантическую модель (а не regexp‑поиск) для уменьшения ложных срабатываний.
- Явное ограничение набора поддерживаемых символов в MVP:
  - локальные переменные в пределах одной процедуры/функции,
  - объявления процедур/функций и их вызовы (если резолвятся статически).

## Ограничения/границы
- Динамические обращения (через строки/рефлексию/косвенные вызовы) не покрываются и должны приводить к fail‑fast (rename) или неполному списку (references) с понятной диагностикой.
- Workspace‑масштабирование: для references/rename по workspace потребуется индекс/поиск по документам; важно не делать блокирующий I/O в hot path.

## Риски
- Неоднозначность резолвинга вызовов в 1С (особенно по метаданным и фасетам).
- Производительность на больших проектах (нужны инкрементальные индексы/снапшоты).
