# Change: refactor-crate-boundaries

## Why
В workspace размыты границы между библиотеками и приложениями: `bsl-agent` (MCP сервер) зависит от `bsl-backend`, который содержит application-слой (web/LSP/системную инициализацию). Это усложняет сопровождение, увеличивает площадь зависимостей и делает рефакторинг рискованнее.

Дополнительно, крейт `bsl-shared` выполняет роль "god object": в нём смешаны базовые доменные типы, репозиторий типов, утилиты и API-структуры, что ухудшает связность и увеличивает стоимость изменений (частые пересборки большого числа крейтов).

## What Changes
- Установить явные правила границ workspace (library vs application crates):
  - `bsl-agent` MUST зависеть только от библиотечных крейтов (не от `bsl-backend`).
- Выделить библиотечный runtime-слой из `bsl-backend`, который можно безопасно переиспользовать в `bsl-agent`:
  - вынести общие компоненты startup/deps snapshot/кэша в отдельный крейт (предварительное имя: `bsl-runtime`).
- Начать декомпозицию `bsl-shared` на более сфокусированные крейты (миграция поэтапная), включая DTO:
  - выделить базовые доменные типы в `bsl-types`,
  - выделить репозиторий/индексы (или их интерфейсы) в `bsl-repository`,
  - выделить API DTO (например, `AnalysisResultDto`, `TypeDto`) в отдельный library crate (предварительное имя: `bsl-api-dtos`),
  - сохранить совместимость в ходе миграции (по возможности без изменения внешнего поведения).

## Impact
- Спецификации:
  - delta к `openspec/specs/dev-workflow/spec.md` (правила границ зависимостей workspace).
- Код (в apply-стадии):
  - новый крейт `bsl-runtime/` (или согласованное имя),
  - новый крейт `bsl-api-dtos/` (или согласованное имя) и миграция `bsl_shared::api::dtos` в него,
  - изменения зависимостей `bsl-agent/Cargo.toml`, `backend/Cargo.toml`, `Cargo.toml` (workspace),
  - рефакторинг модулей `backend/src/system/**` (и смежных) в library-crate,
  - новый(ые) крейты `bsl-types/`, `bsl-repository/` и миграция кода из `shared/`.
- Тесты/quality gates:
  - корректировка тестов, которые создают deps snapshots/startup (если API переместится),
  - `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace`.

## Non-goals
- Переименование `analysis-v2` → `bsl-analysis` (это отдельная миграция и отдельный change).
- Изменение публичных HTTP/MCP контрактов или поведения анализа (за исключением устранения явных багов, выявленных в ходе рефакторинга).
- Полная декомпозиция `bsl-shared` "за один шаг" — только поэтапный перенос, начиная с самых базовых компонентов.
