# Design: VS Code enhanced providers (no stubs by default)

## Принцип
Если extension регистрирует provider в VS Code, он должен:
- либо возвращать осмысленный результат,
- либо быть отключён по умолчанию и явно включаем пользователем (эксперимент).

## Почему это важно
Пустые заглушки:
- не улучшают UX,
- создают “технический долг невидимости” (в коде есть, в продукте нет),
- усложняют тестирование и мониторинг производительности.

## Варианты реализации
1) **Через стандартный LSP**:
   - inlay hints: LSP `textDocument/inlayHint`
   - code actions: LSP `textDocument/codeAction`
2) **Через custom requests** (если нужна richer семантика/DTO):
   - отдельные endpoints вида `bsl/*` с нужными payload.

Для каждого provider’а нужно выбрать вариант и явно зафиксировать.
