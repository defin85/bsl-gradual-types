# Дизайн: v2-only для Web API + CLI + bsl-agent

## Проблема "двух источников истины"

Даже если операции "поиск типов/детали типов" не зависят от IR и не являются inference над кодом,
сейчас они реализованы отдельным сервисом (`TypeInferenceService`), который:
- живёт вне v2 pipeline,
- может эволюционировать независимо,
- создаёт ложное ощущение, что есть допустимый "второй слой" для типовых операций.

Цель — сделать архитектуру однозначной: любые типовые правила и семантика завязаны на v2 deps snapshot
и (если требуется) на v2 queries.

## Предлагаемая структура

### 1) Разделить две категории операций

1. **Repo-only операции (без текста файла):**
   - поиск типов по строке,
   - получение деталей типа/методов/свойств по имени.

   Эти операции должны принимать `Arc<SemanticDeps>` (repo/resolver/signature index) и работать как "read-only view".
   Это v2-only, потому что источник данных — v2 deps snapshot, а не отдельная инициализация/кэш.

2. **Код-зависимые операции (нужен текст/позиции):**
   - диагностики,
   - type_at_position/type_at_byte_offset,
   - semantic tree,
   - hover/completion/signatureHelp/definition.

   Эти операции должны идти через `AnalysisHostV2`/`AnalysisV2` и v2 queries (`parse_result`, `ir`, `type_index`, ...).

### 2) Helper слой вместо `TypeInferenceService`

Вместо `TypeInferenceService` вводим v2-only helper API (место выбирается по факту зависимостей):
- либо `bsl-analysis-v2` (если хотим концентрировать всё "типовое" в v2),
- либо `bsl-backend::application::type_system::web_api_service` (если это презентационный слой для DTO).

Ключевое требование: helper принимает `Arc<SemanticDeps>` и не создаёт/не хранит отдельные кэши/репозитории.

### 3) Запрет legacy фасадов

- Web API / CLI / bsl-agent не должны импортировать `TypeInferenceService`.
- CLI не должен использовать `bsl_shared::engine::AnalysisEngine` для вычисления семантики/диагностик.

## Совместимость

- DTO и HTTP маршруты должны остаться прежними.
- CLI вывод должен остаться прежним (кроме случаев, где ранее он зависел от legacy поведения).

## Верификация

Главная проверка — code-first:
- `rg` на запретные символы,
- тесты, которые фиксируют формат ответа/вывода в местах, где легко допустить регрессию.
