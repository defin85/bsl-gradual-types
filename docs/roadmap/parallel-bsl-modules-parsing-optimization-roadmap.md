# Roadmap: Параллельный парсинг BSL модулей и оптимизация TreeSitterAdapter

**Статус:** 🔴 ПЛАН  
**Приоритет:** HIGH  
**Цель:** ускорить индексацию BSL модулей на старте (web server/LSP/CLI) без потери корректности, сохраняя совместимость с будущим дисковым кэшем.

---

## Контекст (текущее состояние)

- Индексация модулей `*.bsl` выполняется последовательно: `backend/src/data/loaders/config_bsl_modules.rs`.
- Конвертация tree-sitter дерева в AST (BSL) выполняется полностью: `backend/src/system/tree_sitter_adapter/mod.rs`.
- Для индексации модулей достаточно AST без диагностик/линтера.
- Планируется дисковый кэш: `docs/roadmap/disk-cache-platform-config-parsing-roadmap.md`.

---

## Принципы

1) **Семантика не меняется**: экспортные сигнатуры и инференция остаются теми же.  
2) **Безопасная параллельность**: парсинг модулей в параллели, инференция — после сбора данных.  
3) **Совместимость с disk-cache**: чистые, детерминированные результаты парсинга + file-level кэш.  
4) **Наблюдаемость**: прогресс и метрики без шума логов.

---

## Milestones

### M1: Подготовка к параллельному парсингу
**Цель:** отделить стадию "парсинг модулей" от "инференции и записи индекса".

**Критерии успеха:**
- Явно выделена стадия сборки `Vec<ParsedModule>` до инференции.
- Прогресс индексации отражает `current/total` без лишних логов.
- Никаких изменений в результатах тестов.

---

### M2: Параллельный парсинг модулей
**Цель:** парсить модули в несколько потоков (rayon), без изменения семантики.

**Подход:**
- `index_configuration_bsl_modules_parallel` (новая функция) принимает callback: `Fn(ModuleIndexProgress) + Send + Sync`.
- Внутри парсим в `par_iter`, собираем `ParsedModule` и метрики.
- После параллельного этапа выполняем текущую инференцию (`infer_export_param_types_across_modules`) и запись индекса.

**Критерии успеха:**
- Результат индексации идентичен последовательной версии.
- Время индексации на больших конфигурациях ощутимо уменьшается (минимум x1.5 на 4+ ядрах).
- Порядок результатов детерминированный (сортировка перед выдачей/кэшем).

---

### M3: Fast-path для convert_tree при индексации модулей
**Цель:** исключить диагностику и логику lint из индексации модулей.

**Подход:**
- Новый режим `convert_tree_fast` или флаг в `convert_tree`:
  - без `syntax_errors::collect_syntax_errors_cached`
  - без `check_missing_semicolons`
  - без `check_incomplete_new_expressions`
- Использовать fast-path только в `config_bsl_modules`.

**Критерии успеха:**
- Индексация модулей работает быстрее без изменения результата.
- LSP/diagnostics используют полный путь (без регресса в ошибках).

---

### M4: Оптимизация вычисления Span (LineIndex)
**Цель:** снизить аллокации строк при обработке больших файлов.

**Подход:**
- Заменить `Vec<String>` на `LineIndex { line_starts: Vec<usize> }`.
- Вычисление UTF-16 offsets на лету по срезу `&source[range]`.

**Критерии успеха:**
- Падение аллокаций и снижение времени конвертации на больших модулях.
- Тесты на корректность span координат.

---

### M5: Метрики и контроль регрессий
**Цель:** обеспечить наблюдаемость без шума в логах.

**Подход:**
- Добавить агрегированные метрики (top-N медленных модулей по завершению).
- Опциональный debug-режим для детальных таймингов.

**Критерии успеха:**
- В обычном режиме лог не шумит.
- При включении debug видно узкие места.

---

## Требования для совместимости с дисковым кэшем

1) **File-level кэш обязателен** для BSL модулей: результат парсинга сохраняется по каждому файлу отдельно.  
2) **Fingerprint** конфигурации строится как **Merkle-дерево** по:
   - BSL файлам,
   - XML метаданным,
   - расширяемым типам артефактов (макеты и др.).  
3) **Хеш**: `blake3` (приоритет на скорость).  
4) **Детерминизм результата**: перед записью/выдачей сортировать списки сигнатур/локаций.  
5) **Слой B** должен включать `definition_locations` и `global_definition_locations`.

## Риски и ограничения

- Параллельность повышает расход памяти: важно контролировать batch size/threads.
- Fast-path не должен использоваться для LSP diagnostics.
- Изменение Span вычислений требует точного тестового покрытия.
