# Roadmap: Оптимизация парсинга очень больших BSL модулей

**Статус:** 🟡 В ПРОГРЕССЕ  
**Приоритет:** HIGH  
**Цель:** ускорить парсинг модулей 100k+ строк без потери данных (полная эквивалентность результатов).

---

## Контекст (текущее состояние)

- Есть параллельный парсинг модулей + fast-path `convert_tree_fast`.
- Самые медленные модули — очень большие (100k+ строк).
- Нужны сопоставимые результаты (decls + call-sites + типы параметров/возвратов).
- Добавлен compare-режим с прогрессом и флагом `--skip-ast` для замеров single-pass.
- В single-pass добавлены два режима: `Lite` (без `return_type`) и `Full` (с `return_type`).

---

## Принципы

1) **Без потери данных**: результаты индексации эквивалентны текущему pipeline.  
2) **Детерминизм**: одинаковый ввод → одинаковый вывод.  
3) **Совместимость с disk-cache**: file-level результаты пригодны для кэширования.  
4) **Минимальные побочные эффекты**: не ломать LSP/diagnostics.

---

## Milestones

### L1: Переиспользование tree-sitter Parser на поток (thread-local)
**Цель:** снизить накладные расходы на создание Parser и установку языка.

**Подход:**
- `thread_local!` для `tree_sitter::Parser`.
- В каждом потоке один `Parser`, повторно используемый для всех модулей.

**Критерии успеха:**
- Время индексации падает без изменения результата.
- Нет гонок/побочных эффектов при параллельном парсинге.

**Статус:** ✅ ВЫПОЛНЕНО

---

### L2: Однопроходный сбор decls + call-sites из tree-sitter
**Цель:** убрать лишние обходы и создание полного AST, сохранив семантику.

**Подход:**
- Собрать export decls и call-sites напрямую из tree-sitter.
- Перенести текущие эвристики типов аргументов в single-pass extractor.

**Критерии успеха:**
- Результаты эквивалентны текущему AST-пайплайну.
- Ускорение на 100k+ строках заметное (>= x2).

**Статус:** 🟡 В ПРОГРЕССЕ

**Текущее состояние:**
- Реализован single-pass extractor (decls/call-sites) с `SinglePassMode::Lite/Full`.
- Full режим вычисляет `return_type` без AST.
- Добавлен compare-инструмент с прогрессом и флагом `--skip-ast` для чистого single-pass замера.

---

### L3: Инкрементальные оптимизации выделений
**Цель:** убрать лишние аллокации на больших файлах.

**Подход:**
- Резервирование размеров `Vec` по оценке.
- Снижение копирований при `node_text`.

**Критерии успеха:**
- Снижение аллокаций и времени парсинга на больших модулях.

---

### L4: Наблюдаемость
**Цель:** измеримость без шума в логах.

**Подход:**
- Метрики времени по стадиям (enable/disable флагом).
- Сводка top-N медленных модулей.

**Критерии успеха:**
- Метрики включаемы, лог не шумит по умолчанию.

**Статус:** 🟡 В ПРОГРЕССЕ
